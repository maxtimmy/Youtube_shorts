# Original Shorts Studio

Локальный прототип для исследования трендов и производства **самостоятельных вертикальных видео**. Проект помогает вести медиатеку, запускать n8n-процессы рендера и публикации и следить за YouTube-каналами через локальную панель.

> Проект не предназначен для скачивания и перезалива чужих TikTok, Shorts или Reels. Тренд — это сигнал для исследования, а не разрешение копировать ролик. Перед использованием любого исходника нужно подтвердить права, лицензию и соответствие правилам платформы.

## Состояние проекта

Это ранний локальный прототип, а не готовый SaaS:

- панель и Docker-конфигурация находятся в репозитории;
- схемы прикладных SQLite-баз создаются версионируемыми миграциями;
- n8n подключается только через официальный HTTP API и manual webhooks;
- производственные workflow ещё нужно импортировать или настроить отдельно;
- панель не имеет аутентификации — запускайте её только на доверенной машине и не публикуйте порты в интернет.

## Принципы продукта

1. Находим темы, форматы и зрительские потребности, а не копируем конкретный ролик.
2. Создаём новый сценарий, визуальный ряд, озвучку, монтаж и метаданные.
3. Используем только собственные, лицензированные или разрешённые источники и сохраняем подтверждение прав.
4. Перед публикацией проводим ручную проверку качества, прав и правил YouTube.
5. Не автоматизируем обход ограничений, вводящие в заблуждение метаданные, искусственную активность и массовый спам.

Подробный процесс и контрольные точки описаны в [docs/PIPELINE.md](docs/PIPELINE.md), а план развития — в [ROADMAP.md](ROADMAP.md).

## Архитектура

```text
dashboard/          локальная панель и HTTP API (Python + vanilla JS)
banners/            собственные графические ресурсы
docs/               документация процесса и правил
input/              локальные разрешённые исходники (не коммитятся)
output/             рендеры и рабочие SQLite-базы (не коммитятся)
temp/               временные runtime-файлы (не коммитятся)
backups/            локальные резервные копии (не коммитятся)
workflows/          обезличенные экспорты n8n workflow
docker-compose.yml  локальные сервисы n8n и dashboard
Dockerfile.n8n-*    варианты образа n8n для CPU/GPU-окружений
```

Порты по умолчанию:

- n8n: <http://localhost:5678>
- dashboard: <http://localhost:8787>

## Быстрый старт

Требования: Git, Docker Engine и Docker Compose v2.

```bash
cp .env.example .env
python dashboard/cli.py db init
docker compose build
docker compose up -d
```

Проверить состояние:

```bash
docker compose ps
docker compose logs --tail=100 dashboard n8n
```

Остановить сервисы:

```bash
docker compose down
```

Данные n8n сохраняются в именованном Docker volume. Команда `docker compose down -v` удалит их; не используйте её без резервной копии.

## Настройка

Все поддерживаемые параметры перечислены в [.env.example](.env.example). Минимально:

- задайте длинный случайный `N8N_ENCRYPTION_KEY` до первого запуска и не меняйте его для существующего volume;
- добавьте `OPENAI_API_KEY`, только если настроенный workflow действительно использует OpenAI;
- создайте API key n8n и задайте `N8N_API_KEY`, URL API, workflow IDs и manual webhook URL;
- OAuth credentials YouTube создаются в n8n и не должны попадать в Git; dashboard получает только безопасные ID/имена из `YOUTUBE_CREDENTIALS_JSON`;
- оставляйте `N8N_SECURE_COOKIE=false` только для локального HTTP. Для удалённого доступа нужен HTTPS, аутентификация и отдельная оценка безопасности.

## Базы, миграции и резервные копии

```bash
# создать или обновить обе прикладные базы
python dashboard/cli.py db init
python dashboard/cli.py db migrate

# посмотреть версии схем
python dashboard/cli.py db status

# загрузить только обезличенные локальные fixtures
python dashboard/cli.py db fixtures

# создать backup и восстановить его в отдельный каталог
python dashboard/cli.py backup create --label before-change
python dashboard/cli.py backup restore backups/before-change restored-data
```

`db migrate` создаёт датированную резервную копию существующей базы перед первой ожидающей миграцией. Миграции выполняются только вперёд и не удаляют пользовательские базы.

Каждый short по умолчанию получает три проверки со статусом `pending`: права, правила платформы и качество. Карточка доступна в медиатеке dashboard и через `GET/POST /api/shorts/{short_name}/review`. Upload webhook не запускается, пока у всех кандидатов активных сериалов нет трёх решений `approved`; API возвращает `409` и список недостающих проверок.

Обезличенный экспорт workflow:

```bash
python dashboard/cli.py workflows export --destination workflows
```

Перед коммитом экспорт нужно проверить вручную: автоматическая очистка не заменяет проверку на credentials, токены и персональные данные.

## Разработка и проверки

Проект использует стандартную библиотеку Python; runtime-зависимостей у dashboard нет. Инструменты разработки описаны в `requirements-dev.txt`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
pre-commit install
pre-commit run --all-files
pytest
```

Быстрая проверка без установки инструментов:

```bash
python -m compileall -q dashboard
```

Правила участия — в [CONTRIBUTING.md](CONTRIBUTING.md).

## Безопасность и права

- Не коммитьте `.env`, OAuth-токены, cookies, SQLite-базы, исходные и готовые видео.
- Не используйте чужой логотип, голос, лицо, музыку или фрагменты видео без подходящего разрешения.
- «Найдено в интернете» и «сгенерировано ИИ» сами по себе не дают права на публикацию.
- Проверяйте требования YouTube к reused/repetitious content, синтетическим материалам и раскрытию изменённого контента перед каждой существенной сменой формата.
- Не снимайте ручной approval gate в n8n: внешние upload workflow должны выбирать ролики только из представления `publication_ready_shorts`.

Сообщения об уязвимостях не публикуйте вместе с секретами или персональными данными. Создайте приватное обращение владельцу репозитория.

## Известные ограничения

- Миграции покрывают текущую известную схему; перед первым обновлением старой локальной базы всё равно сохраните отдельную копию.
- Производственные n8n workflow не включены: их нужно импортировать и указать IDs/webhooks в `.env`.
- Live YouTube Analytics отключена, потому что безопасный dashboard не извлекает и не расшифровывает OAuth credentials n8n.
- Удаление сериалов через dashboard затрагивает локальные файлы, поэтому перед использованием нужна резервная копия.
- Лицензия проекта не выбрана. До добавления файла `LICENSE` права на повторное использование кода автоматически не предоставляются.
